# IncomSG V4 — Gap Analysis

**Date:** 2026-11-16
**Baseline Branch:** `jack1e2401/version-02` (`817a64d`)
**Integration Branch:** `feat/v4-merchant-self-service`

## 1. Executive Summary

The existing codebase provides a solid multi-merchant foundation for authentication (`ADMIN`, `MERCHANT`, `MEMBER`), merchant applications, basic products, inventory (`InventoryBalance` / `InventoryMovement`), orders/payments (mock + VNPay), refunds (`REFUND_PENDING` -> `REFUNDED`), vouchers, exact fractional loyalty (`Decimal(38,12)`), and platform fee ledger (`MerchantFeeTransaction`).

However, to become a **Multi-Merchant Self-Service & E-commerce Platform (V4)**, there are five major capability gaps across Storefront/Branding, Product Catalog V2, Event CMS, Customer 360° & Auto-Membership, and Merchant Analytics V1.

## 3. Existing Code & Contracts Preserved Unchanged

- **Loyalty & Tier Engine** (`loyalty.calculation.ts`, `loyalty.earning.ts`, `loyalty.reservation.ts`, `loyalty.config.ts`, `LoyaltyPolicyVersion`): untouched.
- **Order & Payment & Refund State Machines** (`orders.repository.ts`, `payments/`, `vnpay`): untouched, except `OrderItem` & `Order` gain read indexes for Analytics/Customer 360°.
- **Inventory Ledger** (`InventoryBalance`, `InventoryMovement`, `inventory.order.ts`): untouched; Product Catalog V2 reads `onHandQuantity - reservedQuantity` and compares against `Product.lowStockThreshold`.
- **Admin Moderation & Platform Fee Ledger**: untouched (`merchant.finance.ts` serves as the reference convention for `Asia/Ho_Chi_Minh` timezone and `REFUND_PENDING` handling).
- **Demo Mode (`VITE_API_MODE=mock`)**: kept compiling and passing existing `demo-mode.spec.ts` / `mock.test.ts`; V4 features target real backend + MySQL (`BackendRoutes`).
